Generated by tools/protocol_manifest.py against
crates/brain-protocol/src, which is the server's own definition of the
wire format. Refresh it the same way the corpus is refreshed — a
deliberate, reviewed step, never fetched in CI:

    ./tools/check_protocol.sh --refresh <brain-checkout>

The manifest records every struct (fields, types, serde attributes, and
declaration order, which is CBOR map order), every enum (variants,
discriminants, and whether it encodes as an integer or a tagged value),
and every opcode. tools/compare_rust.py checks the Rust SDK against it;
tools/compare_bindings.py checks Python and TypeScript against the Rust
SDK, which serde keeps tied to the wire.

The parser reports anything it cannot read under "unparsed" rather than
dropping it, so a manifest with a non-empty unparsed list is not
trustworthy. It is currently empty for all 277 structs and 81 enums.

Generate it from a CLEAN checkout of that commit, never from a dirty
working tree. The manifest is a claim about what the server *ships*, and a
manifest built over uncommitted work pins the SDK to a wire format no
released server speaks. `--refresh` builds from `git archive <commit>`
and refuses a dirty protocol source, so the working tree cannot leak in.
